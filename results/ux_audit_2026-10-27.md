# ShelfScan UX audit — 27 Oct 2026 (local only, NOT deployed, NOT pushed, NOT submitted)

Scope checked: live EC2 app (local code, because the EC2 IP is blocked
for text fetch in this session), Lambda demo-only link, public Devpost
page (fetched), public GitHub repo (fetched, commit 3dc6071), YouTube
v3 (title/description fetched; playback/processing could not be
verified here — parent already has a re-upload task running).

Headline for all surfaces: shelf-state first, counting as an estimate
only. Never an exact stock count, never a brand/SKU claim.

## Verdict in 10 seconds

A judge landing anywhere should get, in order: what it is, what to
click first, what Full/Low/Gap/Check means, and what NOT to trust.
Before this audit, none of the surfaces did that cleanly: the app
opened with two dense paragraphs and seven equal buttons, the Lambda
link opened as raw JSON, Devpost opened with "Try it in 2 minutes"
then a local-setup step, and GitHub opened with COCO-era counting
language. The local fixes below fix the text layer; the structural
gaps (P0-2, P0-3) still need a parent decision and a redeploy.

## P0 — fix before judging, or judges will be misled

1. **Live dashboard claims vs counting claim mismatch (CRITICAL).**
   The validated single-class "product" counter (MAE 7.0, 5 held-out
   photos) is in `app/product_counter.py` and its test, but it is
   NOT wired into `app/main.py` / `app/inference.py`. The live
   dashboard still runs COCO and can still label a shelf
   "refrigerator" or a tin "cell phone". Devpost and video claim
   the single-class estimate. Fix honestly, in this order:
   (a) wire `ProductCounter` into the dashboard, or (b) keep the
   honest-limit note added to `index.html` in this audit ("live
   detections still use COCO; single-class counter is validated
   offline and not yet wired in") on every surface. Do NOT ship a
   dashboard that silently shows COCO labels next to a Devpost
   page claiming single-class counting.

2. **Lambda demo-only link is raw JSON to a human.**
   Live root returns JSON (`service`, `mode`, `links`), and
   `/health` / `/api/demo` return JSON only. A judge clicking it
   sees a code blob, not a product. Prepared fix (needs a Lambda
   redeploy, which I did NOT do): serve a small styled HTML page
   at `/` with: "Demo only — no camera, no OpenCV here", two big
   buttons for /health and /api/demo, the staged Gap 3-vs-8
   explanation in plain words, and links to the full EC2 app,
   Devpost, and video. Keep `/health` and `/api/demo` as JSON
   exactly as they are; only the root page changes. Do NOT claim
   the Lambda page is the full app.

3. **Public Devpost and GitHub copies are older than local files.**
   Public Devpost (fetched) still says "Try it in 2 minutes",
   plain-text /health and /api/demo, "Tests: 22", submission file
   `shelfscan-submission.zip`, and "Built with (apply as tags in
   the Devpost form)". Local `docs/DEVPOST_DESCRIPTION.md` already
   fixes all of these (30-second JSON check with full URLs,
   evidence strip, Tests 23, v2 ZIP name, no leaked editing copy).
   Public GitHub (commit 3dc6071) still shows the COCO-era README
   opening. Parent must paste/push the local versions — this audit
   does NOT push or submit anything.

  be verified from text fetch; the parent's re-upload task is the
  right next step. Do not swap the Devpost link to a re-upload
  until that replacement is confirmed playable with captions.
- **Confusing links, all surfaces:** keep exactly two demo links
  and label them every time — "Full app (EC2, OpenCV, webcam
  dashboard — run locally for webcam)" vs "Demo-only JSON

  real shelf count. The EC2 URL is plain HTTP (port 8000), not
  HTTPS — judges on strict networks may be blocked; that is a
  known, unfixed limitation, not a UI copy fix.
